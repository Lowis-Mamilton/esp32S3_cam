## 1. 範圍

- 一次做出**完整的介面骨架**：功能選單、三個功能頁、學習流程、參數、系統設定、韌體更新頁
- 韌體還不支援的部分，用**展示模式**的模擬資料運作；接上真的板子時，依照 GET_INFO 回報的功能清單決定哪些功能可以用
- 韌體更新頁這次只做畫面和流程，按下去顯示「即將推出」（真正的燒錄在 M5）

## 2. 版面

主要設計尺寸 1280×720 以上；更小的螢幕不特別支援，只保證不會壞掉。

```
┌─────────────────────────────────────────────────────────┐
│ MXCam Studio   ● 已連線 0.1.0  [展示模式] [中/EN] [連線] │ 上方列
├────────┬───────────────────────────────┬────────────────┤
│ 功能    │                               │ [結果][學習]    │
│ ▣ 顏色  │        即時畫面（大）           │ [參數][程式]    │
│ ▣ Tag   │     辨識框 + ID 標籤            │                │
│ ▣ 人臉  │     中央十字                    │  （分頁內容）    │
│ ────── │                               │                │
│ ⚙ 設定  │                               │                │
│ ⬆ 韌體  │  fps · KB/s                    │ [存到板子] 未儲存│
└────────┴───────────────────────────────┴────────────────┘
```

- **上方列**：產品名稱、連線狀態和韌體版本、展示模式開關、語言切換（繁中 / English）、連線 / 中斷按鈕
- **左側功能列**：顏色、AprilTag、人臉偵測；分隔線下方是系統設定、韌體更新
  - 接上真板子時，GET_INFO 沒列出的功能顯示**灰色**，滑鼠移上去提示「需要更新韌體」
  - 展示模式下全部都能用
- **中間**：大的即時畫面（320×240 等比例放大）、辨識框、中央十字，左下角顯示 fps 和 KB/s
- **右側分頁**：
  - **結果**：目前每個辨識結果的 ID、名稱、x、y、寬、高（R4 實際收到的數字）
  - **學習**：已學習的 ID 列表（顏色色塊、名稱可編輯、單獨刪除），「全部忘記」要確認
  - **參數**：目前功能的參數（見第 4 節）
  - **程式**：目前功能的 Arduino 範例程式（用 MXCam 函式庫），有「複製」按鈕；API 先照 SPEC §6.3，M4 再對齊
  - 底部：「存到板子」按鈕；有沒存的變更時顯示「未儲存」

## 3. 辨識框和標籤

| 情況 | 樣式 | 標籤 |
|---|---|---|
| 還沒學習的目標 | 白色細框 | 類別，例如「顏色」 |
| 已學習的顏色 | 該 ID 的固定顏色（顏色 ID 為 1–7） | `ID1 紅色積木`；沒名字就 `ID1` |
| AprilTag | 依 tag ID 取固定顏色（tag ID 在 1–7 色之間循環，人臉用第 8 色） | `Tag 3`；有名字就 `Tag 3 起點` |
| 人臉 | 固定顏色 | `人臉 92%` |
| 手勢 | 手勢 ID 1–9 用 `--id-1`…`--id-8` 循環（9 與 1 同色，和 TFT 一致）；ID 0（有手但認不出）用白色細框 | `讚 92%`、`手 81%`（ID 0）；幫手勢取名後用名字，如 `前進 92%`。功能列用 lucide `Hand`、分類色 `--cat-gesture`（#29b6f6） |

**暫停預覽（2026-11-19）**：即時畫面下方「鏡像顯示」旁有「暫停預覽」開關，預設關、**不記住**（重新整理或重新連線就回到關）。開啟時板子不再送畫面（只送結果，STREAM_START flags 0x02），所有功能與展示模式都適用：
- 畫面區改成深色佔位（不留停格的舊畫面），中央提示「預覽已暫停（辨識照常進行）」；辨識框與標籤照常畫，位置仍跟著鏡像開關
- 左下角的數字改顯示**結果更新率**（「結果 4.1/s」，每秒統計），不是畫面 fps，也不顯示 KB/s
- 結果分頁照常更新；暫停時十字準心隱藏（沒有畫面可對準）

**鏡像顯示（ADR-0010）**：即時畫面左下角有「鏡像顯示」開關（預設開，記在這個瀏覽器）。開啟時畫面、辨識框和學習區域都以鏡像呈現，像照鏡子；協定與結果分頁的座標永遠是鏡頭真實影像座標（R4 收到的數字），結果分頁在鏡像開啟時於表格下方提示這一點。

## 4. 功能參數

| 功能 | 參數 |
|---|---|
| 顏色 | 顏色容許範圍、最小面積、最多回傳幾個（1–8）、是否顯示名稱 |
| AprilTag | tag 家族（固定 tag36h11，只顯示）、幫 tag ID 取名、是否顯示名稱 |
| 人臉偵測 | 偵測門檻、最多回傳幾個（1–8） |
| 手勢辨識 | 偵測到手的門檻（10–95）、手勢門檻（0–100）、最多幾隻手（1／2，提示「兩隻手較慢」）；手的門檻預設值 40（2026-11-19 真手驗收後定案） |

| 共用 | 幫 ID 取名；設定**匯出成 JSON 檔 / 從檔案匯入** |

人臉偵測（真板子，GET_INFO 回報功能 3 才能選；否則灰掉並提示「需要更新韌體」）：門檻（0–100）與最多回傳幾個（1–8）透過 SET_CONFIG 立即生效，並出現「未儲存」標記，存到板子才寫入快閃。門檻滑桿下方提示「門檻低於 50 不會多找到臉」（偵測器第一階段有固定的截斷值）。學習分頁只顯示「人臉偵測不需要學習」，Studio 不會對功能 3 送 LEARN 或 SET_NAME。程式分頁的範例使用 `MXCAM_ALGO_FACE` 並印出 `r.confidence`。

- **名字長度**：最多 48 bytes（UTF-8；一個中文字 3 bytes），超過時輸入框提示，不送出
- **匯入（連著真板子時）**：只套用參數、系統設定和名字；顏色名字只在板上同一 ID 的顏色相符時才套用；學到的顏色無法從檔案重建，Studio 提示「顏色需要重新學習」。匯入後仍要按「存到板子」才寫進 flash（SPEC §6.2）

## 5. 顏色學習

- **框選**：在畫面上拖曳一個框，取框內的顏色，分配下一個 ID
- **學習中央**：按鈕，學中央十字所在位置的顏色（HUSKYLENS 的方式）
- 學到的顏色可以單獨刪除；「全部忘記」要確認
- 最多 7 個顏色 ID（SPEC §3）

### 手勢取名（不需要學習）

手勢辨識（功能 8）有 9 種固定手勢，學習分頁顯示「手勢辨識不需要學習（9 種固定手勢），可以幫手勢取名」，下面是 9 列固定的取名表（手勢名稱｜名字輸入｜清除），做法同 AprilTag：送 SET_NAME 8／FORGET 8，名字上限 48 bytes。Studio 不會對功能 8 送 LEARN。取名後即時畫面與 TFT 以外的標籤（Studio）改顯示名字。

## 6. 系統設定頁

- 裝置資訊：韌體版本、git、序號、解析度
- 通訊：UART 鮑率（115200 / 9600）、I2C 位址（預設 0x5A）
- 狀態燈（RGB LED）亮度
- 恢復原廠設定（要確認）
- TFT 背光是硬體接死的，**不提供亮度設定**；介面語言是網頁自己的設定，放在上方列

## 7. 生效與儲存

- 調參數、學 ID、取名字會**立刻生效**
- 按「**存到板子**」才寫進 flash；沒存時顯示「未儲存」
- 沒存就斷電，板子重開後回到上次儲存的狀態

## 8. 展示模式

- 不用接板子，網頁自己用程式畫出模擬場景：幾個會移動的彩色圓形、一張 AprilTag 圖、一個簡單的人臉圖案
- 手勢功能：一隻卡通手每 1.5 秒換一個手勢（0–9 輪流），每 12 秒有一半時間出現第二隻手（左右分開）；辨識規則與韌體相同（門檻、排序、`maxHands` 1／2 有差別）
- 暫停預覽在展示模式也可用：停止畫圖、結果照送
- 模擬的辨識結果跟著場景移動；學習、取名、參數、存檔都能完整操作（存在瀏覽器記憶體裡，重新整理就清掉）
- 上方列明顯標示「展示模式」，避免誤以為接上了板子

## 9. 外觀

2026-11-19 改版：外觀跟著 **MATRIXblock 新版（beta，strawbArry_beta.0.1）** 的風格走（R4 學生用的積木程式編輯器），讓學生在兩個工具之間不覺得陌生（ADR-0015）。顏色、圓角、陰影用跟 beta 相同的數值，CSS 是自己重寫的；**不使用 MATRIX 的 logo、名稱、圖片或文字**，也不暗示是 MATRIX 的產品。

- **淺色系，只有淺色**：不做深色模式（MATRIXblock 也只有淺色）。即時畫面外圍保留深色框，畫面本身仍是黑底
- **基本數值**：強調色青綠 `#008184`（hover `#027274`、淡底 `#E4F2F2` / `#CFE8E8`），底色 `#F5F6F7`，卡片白色、次要底 `#F7F8F9`，框線 `#E3E5E8` / `#CFD3D8`，文字 `#1D1D1F` / `#6E6E73` / `#9A9AA0`；成功 `#2EAA5D`、警告 `#F0AD4E`、危險 `#D9534F`；圓角 8 / 10 / 14 / 20 px；陰影 `0 8px 24px rgba(0,0,0,.08)`
- **上方列**：白底、下緣細線，高 52 px。左邊「MXCam Studio」粗體字（暫時不放 logo）＋「展示模式」淡青綠標籤；中間是連線狀態（白色圓角框、帶光暈的狀態點、韌體版本）；右邊是展示模式開關（青綠）、語言切換（膠囊分頁）、連線（實心青綠按鈕）/ 中斷（無框按鈕）
- **左側功能列**：白底窄欄，每項是一個彩色圓形圖示、下面是小字標籤。分類色：顏色 `#F65974`、AprilTag `#FFA828`、人臉 `#A56BFF`、設定 `#3ACE3A`、韌體 `#DC8F47`。目前所在項目淡青綠底、圖示外圈青綠光環；不能用的功能圖示變灰
- **中間**：近白點格工作區（`#FCFCFC`）。即時畫面上方掛一個「帽子積木」寫目前功能（顏色辨識 / AprilTag 辨識 / 人臉偵測），畫面放在深色框裡；下方「學習中央」是積木按鈕（左邊圖示區＋分隔線），操作提示是虛線膠囊，鏡像顯示是白色膠囊
- **積木**：深青藍 `#196887`，左側圖示區用較深的分隔線隔開，上方凹口、下方凸塊；數值是白色圓角膠囊，固定選項（tag36h11）是較深底、淺框線的下拉欄位樣式。參數分頁每個參數都是一個積木，滑桿是白色把手；不能操作時積木變灰。系統設定頁的狀態燈亮度也用同一種積木
- **右側面板**：灰底，上方是膠囊分頁（選中的淡青綠底、青綠字），下面是一張白色圓角卡片（分頁內容），卡片底部是「存到板子」那一列。「未儲存」用警告色的小標籤（淡黃底、琥珀點）
- **程式分頁**：白底細框的程式碼區，行號、淺色 Arduino 語法上色（註解、字串、關鍵字、型別、常數、數字），「複製」是小的框線按鈕
- **學習分頁**：已學習的 ID 放在一張圓角卡片裡，每列之間有分隔線（像設定清單）
- **系統設定頁**：白色圓角頁面，大標題；每一區是一個圓角框的分組清單（列與列之間有分隔線），鮑率是分段切換、I2C 位址是一般輸入框
- **韌體更新頁**：兩張大圓角卡片（像 beta 的套件卡片），上半部是內嵌的扁平鋼藍色插圖（`#2D5878` / `#8FB0C8`）
- **確認**（全部忘記、恢復原廠設定）：仍在頁面內，做成對話框樣式（粗體問題、分隔線、右下角按鈕，危險按鈕紅色）；不用瀏覽器的 alert / confirm
- **辨識框顏色不變**：`--id-1`～`--id-8` 與韌體 TFT 的 `k_id_colors` 一致，不能改；中央十字與框選虛線用亮青色，在黑底畫面上比較清楚
- 字型：系統無襯線字（-apple-system / Segoe UI / PingFang TC / 微軟正黑體 / Noto Sans TC），程式碼用 Cascadia Mono / Consolas
- 介面語言：繁體中文、English，可切換，記住使用者的選擇
