# 線條追蹤與物體追蹤自己用純 C 寫

功能 4（線條追蹤）和功能 5（物體追蹤）都沒有適合直接搬到 ESP-IDF 的現成元件：OpenMV／HUSKYLENS 的做法綁在它們自己的影像庫上，esp-dl 沒有這兩種模型。跟顏色（ADR-0009）一樣，我們自己寫純 C 元件，在電腦上用合成畫面做單元測試，CI 的 host-tests 把關。兩個功能都只吃 320×240 RGB565（big-endian）畫面，座標一律是真實影像座標（ADR-0010）。

## 線條追蹤（`mxcam_line`）

1. **灰階共用 `mxcam_gray`**：公式與 AprilTag 相同（`Y = (77R + 150G + 29B) >> 8`，通道先展開到 8 bit），提供逐點 `mxg_luma_be` 和 160×120（2×2 平均）的 `mxg_half`。表格在編譯時產生（const），沒有初始化、可重入。線條與物體追蹤各自呼叫它、各自一份 19.2 KB 的 PSRAM 緩衝區（一次只跑一個功能，空間不是問題，模組邊界簡單）；`mxcam_tag` 不動。
2. **三種模式**：`0` 自動深線（預設，黑膠帶白紙）、`1` 自動淺線、`2` 學到的顏色。「自動」＝ ROI 灰階直方圖的 Otsu；門檻值參數 `0` 表示自動、`1–255` 固定（模式 0：`gray < T`，模式 1：`gray > T`）。Otsu 兩類平均差 < 40（`MXL_MIN_CONTRAST`）視為「沒有線」，避免白紙的雜訊被切成線。
3. **學到的顏色**沿用顏色功能的 HSV 規則（ADR-0009）：逐點比對 `mxc_match_px` 與 `mxc_same_color` 是同一個 HSV 窗（主機測試對全部 65536 個 RGB565 值比對過）。LEARN 功能 4 取區域平均色（`mxc_sample`）並把模式設成 2；FORGET 4 清掉並改回模式 0；**模式 2 但沒學過時照模式 0 跑**（不會卡在永遠 0 筆）。黑／白膠帶沒有飽和度、學不到，Studio 提示改用自動模式。
4. **分帶＋最小平方法**：在 160×120 上只看下方 `roi_pct`%（預設 60%），切成 `bands` 條橫帶（預設 8，帶 0 在最下面）。每帶每欄「有一半以上的列是線」才算有線，連續有線的欄是一段，寬度（換成 320 px）在 `[min_width, max_width]` 內才有效；比 `max_width` 寬的段設 `CROSS`（十字／T 字路口、橫線，或大片陰影）。由下往上，每帶選離預測位置最近的有效段（還沒選到任何帶時用上一張的底端位置，沒有就用中央；選到 1 帶後用它；之後用前兩個選中帶外插）。**抓線規則**：選到第一帶之前沒有距離限制，沒有線的帶也不算跳過（線的下端被擋住、或從畫面側邊進來時，仍能從上面的帶抓到）；選到第一帶之後，離預測超過 max(8, 2 × 帶高)（半解析度 px）就跳過該帶，連續 2 帶跳過就停，只用停之前的帶。某帶有 2 段以上 → `BRANCH`。選中的帶 < 2 → 0 筆。最後對選中帶的中心做最小平方法 `x = a·y + b`，只回報**一條主線**＋角度、偏移、兩端點與旗標（protocol.md 的 14 bytes extra）。
5. **陰影**：畫面一半被陰影蓋住時，Otsu 可能把陰影也切成「深色」；陰影比 `max_width` 寬，所以只會設 `CROSS`，不會被當成線，線本身仍找得到（主機測試 `shadow_half_frame`）。

### Considered Options

- **OpenMV 的 `find_line_segments`／Hough 直線偵測**：綁定 OpenMV 的影像庫；Hough 對每張畫面的計算量比分帶掃描大得多（ESP32-S3 上每張預算只有 10 ms）；而且回傳的是一堆線段，不是循跡要的「一條主線＋偏移＋角度」，還要再自己挑線、合併。
- **學習線色當預設模式**：最常見的教材是黑膠帶白紙，黑／白沒有飽和度、用 HSV 規則學不到；所以預設是自動深線，學顏色只給彩色膠帶（多條路線）用。
- **岔路回報成多筆紀錄**：R4 端的學生程式要自己挑線；改成一條主線＋`BRANCH`／`CROSS` 旗標，「遇到路口停下／轉彎」不必自己判斷。

### Consequences

- 每張畫面成本：`mxg_half` 讀整張 320×240（76,800 點，每點 2 次查表），其餘只碰 ROI（預設 160×72 格）：直方圖、遮罩、每帶欄計數各一次，選段與擬合可忽略。預估 ESP32-S3 上 2–4 ms（多半是讀 PSRAM 畫面），低於 10 ms 的目標；模式 2 的灰色像素用整數提早排除，只有有飽和度的像素才做浮點 HSV。實測在 M6 的處理流程整合時量。
- `mxl_detect` 用靜態 PSRAM 緩衝區（約 41 KB，`EXT_RAM_BSS_ATTR`），不可重入；狀態（上一張的底端位置）由呼叫端持有，換功能時清零。
- 寬 14 px 的橫線若剛好跨在兩帶交界、兩帶都不到一半，這一張就看不到 `CROSS`；車子往前走、橫線移進某一帶時就會出現。
- 結果的偏移與角度都是真實影像座標；鏡頭朝前裝在車上時「右」就是車子的右邊，TFT 與 Studio 只在顯示時鏡像。

## 物體追蹤（`mxcam_track`）

1. **一次一個目標，`id = 1`**：LEARN 框選（現有的區域語意，左上角＋大小，目前功能必須是 5）。區域先裁到畫面內，裁完任一邊 < 16 px（`MXK_MIN_BOX`），或範本的灰階標準差 < 6（`MXK_MIN_STD`，沒有紋理）→ 學不到（`BAD_PARAM`）。再 LEARN 就取代舊的物體（名字一起清掉）。
2. **學到的東西（`mxk_model_t`）**：
   - 灰階範本：`mxg_half` 的 160×120 灰階上框內的區域，以面積平均縮到長邊 ≤ 32（不放大；短邊 < 8 時拉到 8）。面積平均用積分圖在格子角落做雙線性內插（分段常數影像的積分圖在每個像素內是雙線性的），格子邊界可以落在像素中間，結果是精確的面積平均。只用整數邊界（每格 1 或 2 px）會讓位置抖動 ±0.5 px，在細紋理上把 1.1 倍尺度的分數壓到跟 1.0 倍一樣，尺度追不上。
   - 32 格色彩直方圖（正規化到總和 65535）：12 個色相（每格 30°）× 2 個飽和度（0.2–0.5、≥ 0.5），飽和度 < 0.2 的像素改放 8 個亮度格。HSV 定義與顏色功能相同（ADR-0009：V = max、S = (max−min)/max、色相照 `rgb_to_hsv`），只用整數算。取樣點與反投影相同：每個 2×2 區塊的左上像素。
   - 學習時的框大小、中心與框內平均色（GET_LEARNED 用）。
3. **每張畫面的 NCC 搜尋**：搜尋窗＝目前框中心 ±（框大小/2 ＋ 框長邊），裁到畫面。比對在「範本尺度」做：每個尺度把搜尋窗從半解析度縮成範本尺度 ÷ 尺度（窗邊長上限 128 格），對縮小後的窗建 sum／sum² 積分圖，NCC 分母 O(1)、分子直接乘加；步長 2 粗搜，最佳點 ±1 細修。尺度＝目前的累積尺度 × 0.9／1.0／1.1（`scale = 0` 時只用 1.0），累積尺度夾在 0.5–2.0，框大小＝學到的大小 × 累積尺度。`confidence = round(max(0, NCC) × 100)`；低於 `threshold` 就是跟丟，**沒有紀錄**。
4. **跟丟與找回**：跟丟時目前範本回到學到的範本。`reacquire = 1`：每張在全畫面算直方圖反投影（每格權重 = `hist[bin]`），用積分圖找目前框大小的最大和視窗，以它為中心再跑一次 NCC 搜尋確認（同一個門檻）。`reacquire = 0`：只在最後的位置繼續找（物體回到原處才會找回）。
5. **範本更新（不漂移）**：分數 ≥ max(門檻, 70)、`adapt > 0`，而且該位置與**學到的**範本 NCC 也 ≥ 門檻時，`live += (patch − live) × adapt / 100`（四捨五入，差很小時不動）。學到的範本永遠不變。
6. **效能上限與退路（設計決定 15 的順序）**：每張先算這一張粗搜的乘加數，超過 `MXK_MAC_BUDGET`（120 萬）時依序：(1) 每張只多試一個尺度（0.9／1.1 輪流，`mxk_state_t.tick`），(2) 粗搜步長 3。小框不受影響（40 px 的框三個尺度約 55 萬次乘加），大約 48–120 px 的框才會用到退路（更大的框搜尋窗被畫面裁掉，反而便宜）。(3)「範本上限 24×24」沒有用到：主機上掃過 16–320 px、各種長寬比的框，套用 (1)(2) 後最多約 116 萬次。
7. **學到的物體存進 NVS**（設計決定 11，Task 4 實作）：跟顏色一樣「LEARN 改記憶體、SAVE 才寫 flash」，放進同一個 store blob（v2）；範本 ≤ 1024 B＋直方圖 64 B＋其他約 20 B。`mxk_model_valid` 給 store 反序列化時檢查（範本大小 8–32、框 ≥ 16 且在畫面內、中心在畫面內）。

### Considered Options

- **只用色彩直方圖的 CamShift／MeanShift**：便宜，但背景只要有同色的東西框就會飄過去，也分不出同色不同花紋的物體；直方圖只拿來在跟丟時提出候選位置，最後一定由 NCC 確認。
- **全畫面 NCC（每張都在整個畫面找）**：160×120 上 32×32 的範本、三個尺度，逐點要約 3,500 萬次乘加、粗搜步長 2 也要約 900 萬次（ESP32-S3 上約 170 ms），遠超過 30 ms；所以平常只搜上次位置附近，全畫面只做便宜的反投影。
- **學到的物體只放 RAM**：斷電就不見；SPEC §1 的用法是「設定好拔掉電腦、R4 單獨運作」，拔電腦通常就是斷電。
- **追多個目標**：HUSKYLENS 的物體追蹤也只追一個；多目標要處理身分交換，R4 端的程式也變複雜。

### Consequences

- 每張畫面成本（ESP32-S3 @240 MHz 估計，實測在 M6 處理流程整合時量）：`mxg_half` 約 2–3 ms（讀 150 KB PSRAM 畫面）；灰階積分圖、每個尺度的重取樣與窗積分圖合計約 1 ms。NCC 內迴圈編出來是每 4 次乘加 18 個指令（zero-overhead loop、`mul16u`），每列另有約 27 個指令（暫存器不夠、存回堆疊），實際約 5.3–5.9 cycles／次：40 px 的框約 55 萬次 ≈ 13 ms，上限 120 萬次 ≈ 26 ms。合計約 17 ms（40 px）、最壞約 29 ms（48–120 px 的框），**很接近 30 ms**；跟丟且 `reacquire = 1` 的那幾張再加反投影約 3–4 ms。實測超過時把 `MXK_MAC_BUDGET` 調低，再不夠就用退路 (3)（範本上限 24×24）。
- 工作緩衝區約 260 KB 放在 PSRAM（`EXT_RAM_BSS_ATTR`）；`mxk_learn`／`mxk_track` 不可重入。追蹤狀態（目前範本、框、跟丟張數）由呼叫端持有、不存檔，換功能或重新 LEARN 時呼叫 `mxk_reset`。
- **細的週期性花紋**（例如格子 ≤ 約 4 個範本像素）可能在粗搜時鎖到差一個週期的位置：粗搜步長 2 時最近的格點可能離真正的峰 1 格，而週期花紋的「錯一格週期」位置分數也很高。真實物體的花紋不是週期的，主機測試用隨機方塊的大框驗證；物體部分移出畫面時也可能回報錯一個週期的框（分數較低），完全移出後就是跟丟。
- 同色但花紋不同的物體（主機測試：紅白格子學好後換成紅白橫條紋）NCC 約 0.42，門檻預設 0.5 會拒絕；把 `threshold` 調很低時可能被騙。
