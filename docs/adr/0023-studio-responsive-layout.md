# MXCam Studio 在手機和平板上也能用：一份網頁、兩種版面

Studio 原本只為電腦設計（頁面最小寬度 1024 px，學習框只能用滑鼠拖）。藍牙連線做好之後（ADR-0022），MXCam 裝在車上時最順手的螢幕其實是手機或平板；老師也常用平板展示。使用者要 Studio 在手機和平板上能用（2026-11-22）。決定：同一份網頁，用 CSS 依視窗寬度切換「寬版」和「窄版」兩種版面，學習框改用 Pointer Events，觸控時把可按的東西放大。外觀（顏色、圓角、積木樣式）不變，仍照 ADR-0015。

## 決定

1. **兩種版面，只用 CSS 切換。** 視窗寬度 960 px 以上是**寬版**：原本的三欄，不變。小於 960 px 是**窄版**：單欄。用 media query 判斷，不用 JavaScript 偵測視窗，也不加任何套件。拿掉 1024 px 的最小寬度；360 px 寬時不能出現橫向捲動。
   - 理由：兩種版面用的是同一份 DOM，之後加功能、加分頁內容，兩邊會一起跟上，不會有「手機版忘了做」的情況。960 px 讓橫放的平板（1024 以上）用寬版，直放的平板和所有手機用窄版。
2. **窄版由上到下**：上方列、功能列（一條可以左右滑的橫條）、即時畫面（滿寬、維持 4:3）、畫面下方的控制（學習中央、暫停預覽、鏡像顯示、提示）、分頁和分頁內容（滿寬）、「存到板子」那一列（黏在螢幕最下面，連同「未儲存」標籤）。
   - 功能列每一項還是彩色圓形圖示加小字；目前所在的項目會自動捲進視野；設定和韌體排在橫條最後面。橫條邊緣有淡淡的陰影表示還能滑。
   - 窄版不顯示畫面上方的「帽子積木」：正上方的功能列已經標出目前的功能，省下的高度留給畫面和參數。
3. **窄版的即時畫面釘在螢幕上方**，下面的分頁內容自己捲動。目的是「一邊調參數、一邊看畫面」。只在視窗高度 600 px 以上才釘住，這時畫面高度最多佔螢幕的 55%；比較矮的螢幕（例如橫放的手機）不釘，整頁正常捲動，畫面高度不超過螢幕扣掉存檔列之後的高度。
4. **上方列在窄版會換行**，不藏任何東西：產品名稱和連線狀態一列，展示模式開關和語言一列，連線／中斷按鈕一列（展示模式沒有這一列）。所有按鈕都保留文字。
5. **學習框用手指和觸控筆也能拖。** 改用 Pointer Events，按下時對畫面區做 pointer capture。`touch-action: none` 只加在「現在可以框選」的畫面區（class `learnable`），所以沒有框選學習的功能（AprilTag、人臉、手勢）在畫面上滑動時，頁面照常捲動。只點一下不拖，不會發生任何事。鏡像開關和座標換算完全沒動；滑鼠的操作方式不變。
   - 同時間只處理一個指標：框選途中第二根手指不算。瀏覽器把觸控收走（`pointercancel`）時，取消這次框選、不學習。
6. **觸控時可按的範圍至少 44×44 px**（`@media (pointer: coarse)`，兩種版面都適用）：按鈕、分頁、清單列的按鈕、功能列項目、上方列的開關和語言、輸入框。滑桿的把手是 44×44 px 的透明觸控區，中間畫一個比較大的圓鈕。
7. **只有滑鼠移上去才看得到的資訊，觸控要有另一條路。** 灰色的功能（韌體沒有、或還沒連線）原本靠滑鼠移上去的提示說明原因；現在點一下，同一句話會出現在上方列下面那一列提示（原本用來顯示「已切換到…（由其他裝置變更）」的地方），4 秒後消失。沒有另外做一套提示元件。窄版時這一列（和錯誤訊息）會黏在螢幕上方，往下捲了也看得到。
8. **系統設定頁、韌體更新頁在窄版是單欄**：每一列的標題在上、控制在下，輸入框和分段切換撐滿寬度，韌體頁的兩張卡片上下排。
9. **瀏覽器沒有 Web Serial 也沒有 Web Bluetooth 時**（iPhone、iPad 上的所有瀏覽器），畫面中間直接說「這台裝置的瀏覽器連不上 MXCam，可以先用展示模式」，下面放一個「開啟展示模式」按鈕；上方列的展示模式開關也還在。
10. **不做**深色模式、不做安裝成 App（PWA）、不加新功能。

### 實作上的選擇

- 窄版要讓「畫面」和「存檔列」對著整頁黏住，所以中間欄（`main.app-center`）、畫面外層（`.stage-wrap`）和右側面板（`aside.rightpanel`）在窄版設成 `display: contents`：它們自己不佔版面，裡面的東西直接排進單欄。標記沒有改，寬版完全不受影響。
- 為了釘住畫面，在畫面外面加了一層 `.ls-pin`（寬版是 `display: contents`，等於不存在）；上方列的連線／中斷按鈕包了一層 `.tb-connect`，窄版才能讓它們自成一列。
- 寬版的上方列順便修了一個原有的問題：視窗不夠寬時，右邊那一組（展示模式、語言、兩個連線按鈕、中斷）會蓋到中間的連線狀態（在 960 px 寬、英文介面實際看到；右邊那一組比上方列的一半還寬就會發生）。現在左右兩邊平分寬度（狀態仍在正中間），某一邊需要比較多就讓給它，再不夠才把右邊那一組換到第二列，不會互相蓋住。
- 最窄的寬版（960–1023 px，以前頁面不會比 1024 更窄）畫面下方的控制放不下一列，提示文字會像窄版一樣換到按鈕下面。

## Considered Options

- **另外做一個手機 App（或另一份手機版網頁）**：可以為觸控從頭設計，原生 App 在 iPhone 上還能用藍牙。沒選是因為要維護兩份介面，每加一個功能就要做兩次；而且 App 要上架、要安裝，Studio「打開網頁就能用」的好處就沒了。
- **用 JavaScript 偵測視窗大小來決定版面**（依寬度渲染不同的元件）：版面可以差更多，例如手機用完全不同的元件。沒選是因為會變成兩套元件、兩套測試，轉向和調整視窗大小時還要處理狀態；CSS 做得到的事不需要它。
- **功能列收進抽屜（漢堡選單）**：最省垂直空間。沒選是因為切換功能是 Studio 最常做的事，收起來之後每次都要多點一下，而且看不到現在有哪些功能、哪些是灰的。橫條只佔約 70 px，滑一下就看到全部。
- **分頁放在螢幕最下面**（像手機 App 的底部導覽）：拇指好按。沒選是因為最下面已經留給「存到板子」（沒存就斷電會掉設定，這一列必須一直看得到），兩列疊在一起會吃掉太多高度；分頁緊貼在它控制的內容上方也比較好懂。
- **窄版把畫面下方的控制也一起釘住**：實作最簡單（整個中間欄釘住就好）。沒選是因為在 360×740 的手機上會多佔約 100 px，參數只剩不到四成的高度。
- **窄版把停用的連線／中斷按鈕藏起來**（沒連線時只顯示連線、連線後只顯示中斷）：英文加兩種連線方式時可以少一列。沒選是因為使用者要求連線／中斷按鈕一直看得到；按鈕換行並不影響使用。

## Consequences

- **各平台的實際情況**：
  - Android 上的 Chrome／Edge 和 ChromeOS：板子燒藍牙版韌體（ADR-0022）就能用藍牙連線，功能和電腦上相同（藍牙的即時畫面最多 5 fps）。
  - iPhone、iPad：所有瀏覽器都沒有 Web Bluetooth，也沒有 Web Serial，所以 Studio 在上面**只能跑展示模式**，連不上 MXCam。這是平台的限制，Studio 這邊無法解決；要在 iPhone／iPad 上連線，得另外做原生 App 或讓 MXCam 走 Wi-Fi（ADR-0022 沒選的方案）。
  - 手機能不能用 USB（Web Serial）要看那個瀏覽器有沒有提供；Studio 不判斷機型，瀏覽器支援哪一種就顯示哪一種連線按鈕。
- **窄版是整頁捲動**，寬版是各欄自己捲動。分頁內容太寬的東西（很寬的表格、程式碼）在自己的區塊裡左右捲，不會把整頁撐寬。之後加的分頁內容不要寫死超過約 330 px 的寬度。
- **窄版靠這些 class 和順序**，改標記時要一起改 `theme.css` 最後面的窄版規則（`pc-app/src/responsive.test.tsx` 和 `pc-app/theme.css.test.ts` 會擋住不一致）：
  - `.app` > `header.topbar`、提示列、`.app-columns`
  - `.topbar` > `.tb-start`、`.tb-centre`、`.tb-end`（> `.tb-switch`、`.tb-seg`、`.tb-connect`）
  - `.app-columns` > `nav.sidebar`（`.nav-item`、`.nav-rule`）、`main.app-center`、`aside.rightpanel`
  - `.stage-wrap` > `.ls-hat`、`.ls-pin`（> `.stage`）、`.stage-actions`
  - `.rightpanel` > `.rp-tabs`、`.rp-tabpanel`、`.rp-savebar`
  - 設定／韌體頁：`.pg`、`.pg-section`、`.pg-row`、`.pg-seg`、`.pg-hex`、`.pg-tiles`
- 新增功能時，功能列會自己變長、照樣左右滑；不需要改版面。
- 斷點：寬版 `min-width: 960px`；窄版 `max-width: 959.98px`；釘住畫面再加 `min-height: 600px`；觸控放大用 `pointer: coarse`；960–1023.98 px 另有一條只管畫面下方控制換行的規則。
- `display: contents` 用在 `main` 和 `aside` 上：在 Chrome 的無障礙樹裡這兩個地標仍然存在（實際檢查過）；其他瀏覽器沒有逐一檢查。
- 窄版上方列在 360 px 寬、英文、兩種連線方式都有時會排成四列（約 200 px 高）。上方列會跟著頁面捲走，不佔釘住的空間。
- 灰色功能的提示出現、消失時，下面的內容會上下移動一列的高度（寬版本來就是這樣）。
- 這次的檢查是用電腦上的 Chrome 模擬各種螢幕大小和觸控做的，**沒有在真的手機或平板上測過**；用真的手指框選、Android 藍牙連線的速度，要等拿到實機再驗收。

## 驗證

- `pc-app` 測試（jsdom 不排版，所以測行為和結構，不測像素）：
  - `src/ui/live/livestage.test.tsx`：滑鼠、手指、觸控筆的 pointerdown／move／up 學到同一個區域（鏡像開著時也是）、有要求 pointer capture、只點不拖不會學習、`pointercancel` 取消、第二根手指不影響、右鍵不框選、只有可框選時才有 `learnable`。
  - `src/responsive.test.tsx`：點灰色功能出現提示並會自己消失；沒有 Web Serial 和 Web Bluetooth 時的說明文字（兩種語言）和「開啟展示模式」；窄版依賴的 DOM 結構與順序。
  - `theme.css.test.ts`：沒有最小寬度、窄版和釘住畫面的 media query、`touch-action: none` 只在可框選的畫面區、觸控的 44 px 規則。
- 瀏覽器（Chrome 模擬，展示模式）：360×740、390×844、768×1024、1024×768、1280×800，另外看了 740×360（橫放手機）和 960×700。每個功能、每個分頁都檢查：沒有橫向捲動、目前的功能在功能列看得到、存檔列看得到、觸控時沒有小於 44 px 的按鈕。
