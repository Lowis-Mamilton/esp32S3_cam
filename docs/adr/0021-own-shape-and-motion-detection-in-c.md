# 幾何形狀與動態偵測自己用純 C 寫

功能 11（幾何形狀）和功能 12（動態偵測）跟線條、物體追蹤（ADR-0018）一樣，沒有能直接放進 ESP-IDF 的現成元件，所以自己寫兩個純 C 元件 `mxcam_shape`、`mxcam_motion`，用合成畫面在電腦上做單元測試（`host-test/`）。兩個元件都只吃 320×240 RGB565（big-endian）畫面，灰階用共用的 `mxg_half`（ADR-0018 第 1 點），座標一律是真實影像座標（ADR-0010），辨識路徑上不做任何翻轉。工作緩衝區用 `EXT_RAM_BSS_ATTR` 靜態放在 PSRAM，函式裡不 malloc，兩個都不可重入。

## 幾何形狀（`mxcam_shape`，功能 11）

1. **形狀 ID 是固定類別，不需要學習**（同手勢）：`1 圓形 CIRCLE`、`2 三角形 TRIANGLE`、`3 正方形 SQUARE`、`4 長方形 RECT`（ASCII 名稱就是 TFT 標籤，`mxsh_ascii_name`／`mxsh_label` 產生 `SQUARE 90`）。五邊形、星形等**不回報**；ID 5 以後保留。SET_NAME 11 只接受 1–4；GET_LEARNED 11 列出有名字的形狀；FORGET 11 刪名字；LEARN 11 → `BAD_PARAM`。
2. **二值化**：在 `mxg_half` 的 160×120 灰階上做。模式 `0` 深色形狀淺色底（預設）、`1` 淺色形狀深色底。門檻 `0` = Otsu（全畫面直方圖；兩類平均差 < 40 → 沒有形狀，同線條），`1–255` 固定（模式 0：`gray < T`，模式 1：`gray > T`）。
3. **區域與過濾**：8 連通的連通區域，用顯式堆疊（每個像素最多推一次，堆疊 160×120 格，不遞迴）。丟掉：碰到畫面邊緣的（形狀不完整，分類會錯）、外接框長邊（×2 換成 320 px）< `min_size` 的、外接框面積 > 畫面 60% 的（背景、紙張）。
4. **輪廓**：對每個留下的區域，從它在逐列掃描中的第一個像素開始做 Moore 鄰點追蹤，得到外輪廓（像素中心）；起點下一步重複時停。超過 1,024 點的區域跳過。空心外框（用筆畫的形狀）的外輪廓和實心的一樣，所以面積用輪廓算，不數像素。
5. **特徵**：周長 `P` = 各步長度和（8 連通鏈碼：直 1、斜 √2）；面積 `A' = 鞋帶公式面積 + P/2`（像素中心連成的多邊形少了外圍半個像素寬的一圈，補回來後和像素數差不多）；圓度 `C = 4πA'/P²`；形心到各輪廓點距離的變異係數 `CV`。
6. **分類（依序）**：
   - `C ≥ 0.80` 且 `CV ≤ 0.055` → 圓。
   - 否則做 Douglas–Peucker（`ε = max(1, 3% × P)`）：起點取離形心最遠的點、第二個點取離它最遠的點，把封閉輪廓切成兩段分別簡化；之後只要多於 3 個頂點，就把「離兩個鄰點連線最近、而且距離 < ε」的頂點刪掉（起點剛好不在角上時會被刪掉）。保留超過 12 個點就停（不是三角形或四邊形，也限制雜亂區域的計算量）。
   - 頂點數 `n = 3` → 三角形。
   - `n = 4`、凸、四個內角都在 90° ± 20° → 兩組對邊平均長度的比 ≤ 1.25 是正方形，否則長方形。
   - 其他 → 不回報。
7. **ResultRecord**：每個形狀一筆，最多 `max_results` 筆，依 `A'` 由大到小；`id` = 形狀 ID；`x, y, width, height` = 區域外接框（160×120 換回 320：`x0×2`、寬 ×2，中心 = (min + max) / 2 取整）；`confidence` = round(100 × 小 ÷ 大)，比的是 `A'` 與近似形狀加上同樣半像素帶的面積（多邊形：DP 多邊形面積 + 周長/2；圓：以平均半徑 r̄ 算 πr̄² + πr̄）；`extra_len 0`。
8. **Shape config v1**（function_id 11，layout 1，body 8）：`mode u8`（0／1，> 1 → 0，預設 0）、`threshold u8`（0 = 自動，預設 0）、`min_size u8`（px，16–240 夾到邊界，預設 32）、`max_results u8`（1–8 夾到邊界，預設 4）、`reserved u8 ×4`。

**定案的常數**（`mxcam_shape.h`／`.c`）：

| 常數 | 值 | 說明 |
|---|---|---|
| `MXSH_MIN_CONTRAST` | 40 | Otsu 兩類平均差下限 |
| `MXSH_MAX_CONTOUR` | 1,024 | 輪廓點上限 |
| `MXSH_CIRC_MIN` | 0.80 | 圓的圓度下限 |
| `MXSH_CV_MAX` | **0.055**（計畫原為 0.06） | 圓的 CV 上限 |
| `MXSH_DP_EPS_PCT` | 3 | DP 的 ε（周長 %） |
| `MXSH_QUAD_ANGLE_TOL` | 20 | 四邊形內角容許（度） |
| `MXSH_SQUARE_RATIO` | 1.25 | 正方形對邊比上限 |
| `MXSH_MAX_BG_PCT` | 60 | 外接框超過畫面這個 % 就是背景 |
| `DP_MAX_KEEP`（內部） | 12 | DP 保留點數上限（計畫沒有，新增） |

**CV 上限從 0.06 改成 0.055 的理由**：只有 CV 能把正五邊形和圓分開（正五邊形的圓度約 0.82，也會超過 0.80）。理論上正五邊形的 CV 約 0.0635，主機測試裡 R 30／50／70、轉 0°／9°／17°／36° 實測 0.065–0.0725，越大越接近理論值；R 70 時離 0.06 只差 0.005，鏡頭模糊把角磨圓還會再降低。數位化的圓 CV ≤ 0.023，0.9 的橢圓（鏡頭斜約 26°）0.045（主機測試）；理論上 0.055 讓圓能容許到約 31° 的斜度（0.06 是約 32°），只少 1° 卻讓五邊形的餘裕加倍。六邊形（理論 0.046）仍當成圓。其他實測特徵（主機合成畫面）：數位化的圓 `C` 0.93–0.96；正方形 `CV` 約 0.11、`C` 0.71–0.93（小的正方形因為 `P/2` 的補償 `C` 偏高，靠 CV 排除）；三角形 `CV` 約 0.22；五邊形 DP 後都是 5 個頂點。

### Considered Options

- **Canny 邊緣＋Hough（圓與直線）**：要調的參數多（兩個 Canny 門檻、Hough 的累加門檻與半徑範圍），每張的計算量比一次連通區域加輪廓大很多，而且 Hough 找到的是一堆圓與線段，還要再自己組合成形狀。
- **在全解析度 320×240 上做**：區域標記與輪廓的工作量是 4 倍，估計每張要 20 ms 以上，超過 15 ms 的目標；教材的形狀印在 A4 上通常夠大，半解析度就夠。
- **只數 DP 的頂點、不看圓度**：圓用 3% 的 ε 簡化後會變成五、六邊形，沒辦法和多邊形分開；所以先用圓度＋CV 判斷圓，剩下的才數頂點。

### Consequences

- 六邊形以上在 160×120 上和圓分不開，會當成圓；五邊形、星形、橢圓（斜很多的圓）、彎曲的形狀不回報。
- 很淺的顏色（例如黃色）在白紙上灰階差太小，Otsu 的兩類平均差 < 40 就整張不回報；可以改用固定門檻或深色底＋模式 1。
- 碰到畫面邊緣的形狀不回報（要整個在畫面內）；外接框超過畫面 60% 的區域當成背景，所以形狀不能大到占滿畫面。
- 每張畫面成本：`mxg_half` 讀整張畫面（ESP32-S3 上約 2–4 ms，ADR-0018），其餘是 160×120 上的直方圖、遮罩、掃描與連通區域（每個前景像素看 8 個鄰點）各一次，輪廓與分類每個區域約幾百點（DP 最多約 12 × 點數次距離計算）。主機（x86）上 6 個形狀的畫面約 0.15 ms，隨機 4 px 黑白方塊（大量破碎區域）約 0.24 ms；板上的時間在 M7 Task 5 量，超過 15 ms 的退路是輪廓上限改成 512 點、只處理面積前 8 大的區域。
- 工作緩衝區約 89 KB 放在 PSRAM（`EXT_RAM_BSS_ATTR`），`mxsh_detect`／`mxsh_classify` 不可重入；沒有跨畫面的狀態，換功能不用重設。

## 動態偵測（`mxcam_motion`，功能 12）

1. **只有偵測、沒有類別**：`id = 0`（同人臉）。不需要學習、不能取名：LEARN／SET_NAME 12 → `BAD_PARAM`，FORGET 12 成功，GET_LEARNED 12 → `BAD_PARAM`。**只適用於固定不動的鏡頭**。
2. **背景模型**：`mxg_half` 的 160×120 灰階再 2×2 平均成 **80×60** 格（每格 = 320 畫面的 4×4 px）。背景是每格的指數移動平均（`u16`，×16 定點）：每張 `bg += (cur×16 − bg) >> 3`（約 8 張的時間常數，10 fps 約 0.8 秒；負數用明確的向下取整，不依賴有號數右移）。
3. **曝光補償**：每格的差 `cur − bg` 先減掉**全畫面所有格的差的中位數**，再和門檻比（`|差 − 中位數| > threshold` 就是變化格）。中位數用 511 格的直方圖算（每張約 4,800 次累加）。
4. **全域變化**：超過 50% 的格子在動（開關燈、鏡頭被移動、車子在走）→ 背景重設成這張，這張與之後 2 張不回報（`stats.global_reset = 1`）。
5. **暖機**：`mxm_reset`（換到功能 12 時呼叫；開機時的狀態等同重設過）之後前 3 張只建背景（第一張直接當背景，之後兩張照常更新）、不回報。
6. **區域**：變化格做一次 3×3 膨脹（把一隻手的碎片接起來：相隔 2 格以內的會連在一起），再做 8 連通區域（顯式堆疊）。每個區域的框是**區域內真正變化的格子**的外接框（不含膨脹），長邊（×4 換成 320 px）≥ `min_size` 才回報。`confidence` = round(100 × 區域的變化格數 ÷ 框內格數)；依框面積由大到小、最多 `max_results` 筆；`extra_len 0`。框一定在畫面內。
7. **Motion config v1**（function_id 12，layout 1，body 8）：`threshold u8`（灰階差，5–100 夾到邊界，預設 25）、`min_size u8`（px，8–240，預設 24）、`max_results u8`（1–8，預設 4）、`reserved u8 ×5`。

**定案的常數**（`mxcam_motion.h`）：`MXM_W` 80、`MXM_H` 60、`MXM_BG_SHIFT` 3、`MXM_WARMUP` 3、`MXM_GLOBAL_PCT` 50、`MXM_GLOBAL_SKIP` 2（計畫寫在文字裡的「之後 2 張」，做成常數）。

**曝光補償用中位數、不用計畫原本的平均（偏離計畫）**：平均會被移動的物體拉走。一個深色物體占畫面 1/4、和背景差約 120 時，平均差約 −30，減掉後所有靜止的格子都差 +30 > 25，超過一半的格子「在動」→ 被當成全域變化、什麼都不回報（主機測試 `large_object_not_global`：換成平均就失敗）。中位數在物體小於半個畫面時不受影響，整張一起變亮（自動曝光）時又和平均一樣。

### Considered Options

- **前後兩張相減**：只抓得到移動物體的邊緣（物體內部前後兩張一樣），慢的動作幾乎抓不到；移動平均的背景能抓到整個物體。
- **esp-dl 的 `motion_detect`**：只回傳「有幾個點在動」，沒有框，R4 拿不到位置。
- **不做曝光補償**：OV3660 的自動曝光一跳，整張的灰階一起變，所有格子都超過門檻，結果不是整個畫面一個大框，就是每次都觸發全域重設、漏掉真正的動作。
- **只更新沒有變化的格子（選擇性更新背景）**：停下來的物體永遠不會融入背景，一直被回報；計畫要的是 1–2 秒後消失。

### Consequences

- 動態偵測只適用固定鏡頭：手拿著板子晃、裝在會動的車上時，大多數張都會是全域變化（不回報），偶爾晃得少的那張會報出一堆框。寫進 SPEC。
- 停下來的物體約 1–2 秒後融入背景、不再回報（主機測試：黑色方塊停住後第 14 張起 0 筆）。物體離開後，原來的位置也會留下約同樣時間的「鬼影」；暖機時已經在畫面上、之後才離開的物體，第一張背景裡就有它，同樣會留下鬼影。
- 移動物體後面有一段逐漸消失的拖尾，框會比物體長；大而均勻、移動很慢的物體，內部會先被背景吸收（只剩前緣是變化格），紋理很強的背景上拖尾可能斷成幾塊，多出小框（`min_size` 會濾掉大部分）。
- 光線只有一部分變化（例如窗邊的陰影）時，中位數補償不了，那一塊會被當成在動。
- 每張畫面成本：`mxg_half`（約 2–4 ms，讀整張畫面）＋ 80×60 格上的幾次線性掃描（2×2 平均、直方圖、差值、背景更新、3×3 膨脹、連通區域），每格約 30 個簡單運算，約 15 萬次。主機上約 0.1 ms；板上在 M7 Task 5 量，目標 ≤ 5 ms（主要花在 `mxg_half` 讀 PSRAM 畫面）。
- 背景與工作緩衝區約 54 KB 放在 PSRAM（`EXT_RAM_BSS_ATTR`），`mxm_detect` 不可重入；背景是元件內部的狀態，換到功能 12 時呼叫 `mxm_reset`。
