# MXCam 打樣硬體需求表（草稿）

> 狀態：草稿，2026-11-19 起累積。目前用 GOOUUU ESP32-S3 擴展板 V1.3 + 2.8 吋 TFT 驗證功能；這份清單在**打樣時提交給廠商**，列出要改的硬體項目。
> 軟體與規格以 `docs/SPEC.md` 為準；本文件只記錄硬體需求與驗證時發現的問題。

## 1. 主要元件（沿用驗證板）

| 項目 | 規格 | 備註 |
|---|---|---|
| 主控 | ESP32-S3-WROOM-1 **N16R8**（16 MB flash、8 MB octal PSRAM） | 韌體約 2.1 MB（含人臉模型），之後加入更多模型會更大；PSRAM 必須是 octal 8 MB |
| 鏡頭 | OV3660（DVP 8-bit） | 腳位見 SPEC §4；QVGA 320×240 使用 |
| 螢幕 | 2.8 吋 ILI9341 SPI 320×240，**橫向** | 觸控 XPT2046 不需要 |
| 狀態燈 | WS2812 RGB（GPIO48） | |
| USB | 原生 USB（USB-Serial-JTAG）＝電腦連線與燒錄 | 正式版建議只留這個 USB-C；除錯 UART0 留測試點即可 |

## 2. 必須修改

### 2.1 對 MATRIX Mini R4 的電位轉換（⚠️ 最重要）

- ESP32-S3 的 GPIO **不耐 5 V**；MATRIX Mini R4（RA4M1）是 **5 V 邏輯**。
- 驗證階段用現成 BSS138 雙向模組＋杜邦線。**打樣版請在板上做電位轉換**：
  - I2C（SDA、SCL）：雙向（BSS138 或專用 I2C 電位轉換 IC，如 PCA9306），R4 端 5 V 上拉、ESP32 端 3.3 V 上拉，各一組，100 kHz／400 kHz 都要能跑
  - UART（TX、RX）：單向轉換即可（ESP32 TX → R4 RX 升壓；R4 TX → ESP32 RX 降壓）
- 兩邊 **GND 共地**；R4 的 5 V 不可直接接到 ESP32 任何 GPIO 或 3.3 V。

### 2.2 對 R4 的連接器

- 一個連接器同時帶 I2C 與 UART（建議沿用 MATRIX 系列的連接器規格，讓學生直接用原廠線材）
- 腳位：5 V／GND／SDA／SCL／TX／RX（是否由 R4 供電給 MXCam 需評估電流，見 2.3）
- I2C 用 GPIO42（SDA）、GPIO41（SCL）；UART 用 GPIO1／GPIO2（驗證板要拔掉跳線帽 P7、P8，正式版直接走線、不要接電位器與 DHT11）

### 2.3 電源

- 待量測：運作電流（鏡頭＋TFT＋WiFi 不使用）。若要由 R4 供電，需確認 R4 的 5 V 輸出能力
- 電腦 USB 與 R4 同時接上時的電源切換（避免兩個 5 V 對灌）

## 3. 建議修改

- **TFT 背光**：驗證板背光接死常亮；正式版建議接 GPIO 控制（PWM 調亮度或關閉）
- **觸控**：不需要，可省略 XPT2046 與相關腳位
- **TF 卡**：第一版不使用（GPIO38/39/40 保留）；可省略
- **按鍵**：BOOT／RST 保留（網頁燒錄失敗時要手動進入下載模式）
- **鏡頭方向**：使用者面對鏡頭與螢幕拿著板子；正式版的鏡頭與螢幕相對位置與安裝方向要讓 TFT 鏡像顯示自然（ADR-0010）
