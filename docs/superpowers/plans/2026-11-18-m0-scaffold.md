# M0 專案骨架 實作計畫

> **給執行的代理：** 必須搭配 superpowers:subagent-driven-development（推薦）或 superpowers:executing-plans 逐項執行本計畫。步驟用勾選框（`- [ ]`）追蹤進度。

**目標：** 清掉舊程式，建立 `firmware/`、`pc-app/`、`arduino-lib/` 三個可以編譯、可以測試的空骨架和 CI，讓 M1 一開始就有綠燈可以守。

**架構：** 一個 repo 裡放三個子專案，各自獨立建置。CI 用一個 workflow，分三個 job 各別驗證。這個里程碑**不寫任何協定或演算法**，只確認工具鏈和資料夾慣例。

**技術：** ESP-IDF v5.4.1（CI 用 `espressif/idf:v5.4.1` 容器）、Node 22 + Vite + React + TypeScript + Vitest、arduino-cli + `arduino:renesas_uno:unor4wifi`、GitHub Actions。

**規格：** `docs/SPEC.md`（第 6、7、8、9 節）；決策紀錄在 `docs/adr/`。

## 全域限制

- 產品名稱一律用 `MXCam`；電腦軟體名稱用 `MXCam Studio`（名詞見 `GLOSSARY.md`）
- 韌體目標晶片 `esp32s3`，16MB flash、8MB **octal** PSRAM
- 開發者除錯訊息走 **UART0（TTL 孔）**；原生 USB（OTG 孔）保留給協定
- 網頁只支援 Chrome / Edge（Web Serial），之後發佈在 GitHub Pages 的子路徑 `/esp32S3_cam/`
- Arduino 函式庫的目標板是 `arduino:renesas_uno:unor4wifi`
- 授權 MIT，著作權人寫 `MXCam contributors`
- 在 `m0-scaffold` 分支上工作，不直接改 `main`

## 審查重點

規格沒明講、但最容易出事的五種情況：

1. **專案路徑有空白**（`K230 Smart Cam`）：ESP-IDF 在 Windows 上遇到路徑空白常常建置失敗。CI 不受影響，但要在 `CLAUDE.md` 註明本機建置的做法（用 `subst` 對應成磁碟代號，或把 repo 搬到沒有空白的路徑）。由任務 5 寫入。
2. **PSRAM 設成 quad 而不是 octal**：N16R8 會開機後不停重啟。任務 2 要確認 `sdkconfig.defaults` 有 `CONFIG_SPIRAM_MODE_OCT=y`。
3. **Vite 沒設 `base`**：部署到 GitHub Pages 子路徑後，所有資源都會 404。任務 3 先把 `base` 設成 `/esp32S3_cam/`，並用測試確認。
4. **Windows 的 CRLF 換行混進來**：`.gitattributes` 已經有 `* text=auto`；任務 1 再加上 `*.sh text eol=lf`，避免腳本在 CI 容器裡壞掉。
5. **除錯訊息跑到 USB-Serial-JTAG**：會跟之後的協定搶 OTG 孔。任務 2 要確認有 `CONFIG_ESP_CONSOLE_UART_DEFAULT=y` 和 `CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`。
