# 內部 RAM 的最低剩餘：統計少算 32 KB（2026-11-22）

日期：2026-11-22 ・ 韌體 `0f0f595` 加上本次的 `sdkconfig.defaults` 修改 ・ ESP-IDF v5.5.6

## 現象

TTL 埠每秒一行的統計裡，`min`（開機以來最低的內部 RAM 剩餘）一直比 `heap`（當下剩餘）低約 41 KB：`heap=143743 min=102452`。看起來像開機時有一次 41 KB 的尖峰。

## 原因

沒有尖峰。

1. **32,031 B 是統計誤差。** `CONFIG_SPIRAM_MALLOC_RESERVE_INTERNAL` 的 IDF 預設值是 32768：開機時從內部 heap 切出一塊 32 KB 的保留池，給只能放內部記憶體的配置在內部 RAM 用光時使用。這塊池子在這個韌體裡一直是空的，但 `heap_caps_get_minimum_free_size()` 把它的最低值算成 0。
2. **約 9 KB 是 `app_main` 的堆疊**，開機完成後釋放。

證據（在每個開機階段印出 `free`／`min`）：

| 階段 | `free` | `min` | 差 |
|---|---|---|---|
| 進入 `app_main` | 294,667 | 262,636 | 32,031 |
| 鏡頭初始化後 | 226,883 | 194,852 | 32,031 |
| 手勢模型載入後 | 226,411 | 194,380 | 32,031 |
| 開機完成 | 134,787 | 102,756 | 32,031 |

`heap_caps_print_heap_info(MALLOC_CAP_INTERNAL)` 列出的保留池：`len 32767 free 32031 allocated 0 min_free 0`。

## 修改

`firmware/sdkconfig.defaults` 加上 `CONFIG_SPIRAM_MALLOC_RESERVE_INTERNAL=0`，不再切保留池。同一塊記憶體變成主要內部 heap 的一部分，可用總量不變。保留池要防的是「內部 RAM 被用光」，這個專案的底線是最低剩餘 60 KB，不會走到那一步。

已經建置過的工作目錄要自己更新 `firmware/sdkconfig`（刪掉這個檔案重新產生，或把該行改成 0）；`sdkconfig.defaults` 只對還沒有值的設定生效。

## 修改後的實測

人臉、手勢各 10 秒，USB 以 10 fps 串流：

| | 修改前 | 修改後 |
|---|---|---|
| 開機完成時的內部 RAM | 134,787 B | 135,580 B |
| 穩定剩餘（`heap`） | 143,743 B | 144,532 B |
| 統計行的 `min` | 102,452 B | **135,264 B** |
| 人臉 fps／`proc_ms` | 10.1／46.9 | 10.1／46.9 |
| 手勢 fps／`proc_ms` | 5.0／144.7 | 5.0／144.7 |
| `mxcam.bin` | 3,548,560 B | 3,548,208 B |

之前各里程碑量測紀錄裡的 `min`（例如 M8a 的 104,836）都少了 32,031 B；那些文件沒有回頭改。
